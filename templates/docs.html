Dashboard Configuration Docs

What This Dashboard Shows

A plain-language walkthrough of each section, top to bottom, as you'd actually encounter it.

Top bar (Range / Live / Light-Dark)

"Range" picks how far back in time you're looking -- the last 6 hours, 24 hours, a week, a month, or three months. "Live" controls whether the page keeps updating itself automatically every 15 seconds or has been paused. The other button just switches between a dark or light color scheme -- purely cosmetic, no effect on the data.

Active WAN panel

Tells you, right now, which internet connection is actually in use -- your main one or the backup -- and shows the other one's name for reference. If something's gone wrong and the system had to switch to the backup, this is where you'd see that at a glance. The "Switch to [other connection]" button lets you manually force a switch, with a confirmation prompt first since it's a real action that affects live traffic.

The three summary numbers

Degradation windows / total degraded time / failover actions -- a quick scorecard for whatever time range is selected: how many separate stretches of bad internet were detected, how many total minutes that added up to, and how many times the system actually decided to switch connections because of it. The first number can be much bigger than the last -- a brief 10-second hiccup counts as a "degradation window" even if it was never serious enough to trigger an actual switch.

Unresolved Alerts

Pulls directly from the router/network system's own built-in alert log -- things like a device going offline, not something this dashboard invented itself. Each one can be marked as handled ("Acknowledge") once it's been dealt with, which removes it from this list.

Latency & Loss chart

The core health chart. "Latency" is how long it takes for a signal to make a round trip -- think of it as a reaction-time measurement; lower is better, and spikes usually mean something's straining the connection. "Loss" is the percentage of test signals that never made it back at all -- a very blunt but reliable sign that the connection is actually broken, not just slow. The chart's title tells you which of the two connections (main or backup) this data is currently describing, since that can change if a switch happens.

WAN Metrics (tabs per connection)

Each tab is one physical internet connection, and shows two things together: how much data is actually flowing through it (throughput) and its latency, as reported directly by the router itself rather than measured indirectly. Useful because it can show you the backup connection's health even while it's sitting idle and not currently in use -- something the main chart above can't do. This data only refreshes about every 5 minutes on the router's own schedule, which the dashboard tells you honestly rather than pretending it's instant.

Degradation windows table + CSV download

A detailed log: every stretch of bad connectivity, with exact start/end times, how long it lasted, and how bad the latency and loss got during it. The download button exports this as a spreadsheet-style file -- handy if you ever need to show an internet provider evidence of an ongoing problem. Worth knowing: this is your own equipment's measurements, not an official or certified reading, so it's useful as supporting evidence in a conversation, not as some kind of legal proof.

Speed Test

Lets you manually trigger a real speed test on a specific connection and watch the result come in live -- same idea as any online speed test site, just run through the router itself and aimed at whichever connection you pick from the dropdown. Not every router model/firmware actually supports this feature -- if yours doesn't, this section explains that plainly instead of showing a button that would just fail.

Configuration

A separate page (linked above) for viewing and adjusting the underlying settings -- things like which addresses get pinged, how sensitive the failover trigger is, connection credentials, and the display names shown for each internet connection. Sensitive fields like secret keys are hidden by default with a toggle to reveal them. After saving, the "Apply & Restart" button puts changes into effect automatically -- the dashboard goes away for roughly 10-30 seconds and comes back on its own, with monitoring resuming automatically. The two connection display names are the exception: those apply immediately on the next refresh, no restart needed.

Danger Zone (this page and Configuration)

Each page with a Danger Zone requires typing a confirmation word before anything happens, since these actions are deliberately hard to trigger by accident. On the main dashboard, it permanently erases historical charts and logs (but not which connection is currently active). On the Configuration page, it reverts every setting back to its original configured/default value (but doesn't touch the historical data).
